# Chirpy 🐦

A Twitter-like social media backend API built with Go. Chirpy allows users to create accounts, post short messages ("chirps"), and manage their content with full authentication support.

## Features

- **User Management** - Create accounts, update profiles, and manage user data
- **Authentication** - JWT-based authentication with refresh tokens and secure password hashing
- **Chirps (Posts)** - Create, read, update, and delete short messages
- **Premium Features** - Chirpy Red subscription support
- **Webhooks** - Integration with Polka webhooks for premium upgrades
- **Metrics** - Built-in metrics tracking for monitoring
- **Type-Safe Database Access** - Using sqlc for generated SQL code

## Tech Stack

- **Language**: Go 1.25.1
- **Web Framework**: net/http (Go standard library)
- **Database**: PostgreSQL
- **Authentication**: JWT (golang-jwt/jwt/v5)
- **Password Hashing**: Argon2id
- **SQL Code Generation**: sqlc
- **Database Migration**: Goose
- **UUID**: google/uuid

## Project Structure

```
chirpy/
├── internal/
│   ├── api/          # HTTP handlers and API logic
│   ├── auth/         # Authentication utilities (JWT, hashing, tokens)
│   └── database/     # Database queries (generated by sqlc)

├── main.go           # Application entry point

```

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/andriyzaec/chirpy.git
cd chirpy
```

### 2. Set up environment variables

Create a `.env` file in the project root:

```env
DB_URL=postgres://user:password@localhost:5432/chirpy_db
PLATFORM=local
JWT_SECRET=your-secret-key-here-change-in-production
POLKA_KEY=your-polka-api-key-here
```

### 3. Set up the database

```bash
# Create the database
createdb chirpy_db

# Run migrations (using goose)
goose -dir sql/schema postgres "$DB_URL" up
```

### 4. Install dependencies

```bash
go mod download
go mod tidy
```

### 5. Run the server

```bash
go run main.go
```

The server will start on `http://localhost:8080`

## Database Schema

### Users Table
```sql
CREATE TABLE users (
  id UUID PRIMARY KEY,
  created_at TIMESTAMP NOT NULL,
  updated_at TIMESTAMP NOT NULL,
  email TEXT UNIQUE NOT NULL,
  hashed_password TEXT NOT NULL,
  is_chirpy_red BOOLEAN NOT NULL DEFAULT false
);
```

### Chirps Table
```sql
CREATE TABLE chirps (
  id UUID PRIMARY KEY,
  created_at TIMESTAMP NOT NULL,
  updated_at TIMESTAMP NOT NULL,
  body TEXT NOT NULL,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE
);
```

### Refresh Tokens Table
```sql
CREATE TABLE refresh_token (
  token TEXT PRIMARY KEY,
  created_at TIMESTAMP NOT NULL,
  updated_at TIMESTAMP NOT NULL,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  expires_at TIMESTAMP NOT NULL,
  revoked_at TIMESTAMP DEFAULT NULL
);
```

### Code Generation

The project uses **sqlc** for type-safe SQL code generation.

To regenerate database code after modifying SQL queries:

```bash
sqlc generate
```

Configuration is in `sqlc.yaml`.

### Code Style

This project follows Go conventions:
- Use `gofmt` for formatting
- Run `go vet` to catch common mistakes
- Keep packages focused and small
- Export only what's necessary (capitalize public symbols)

### Adding New Features

1. **Add database schema migration** in `sql/schema/`
2. **Add SQL queries** in `sql/queries/`
3. **Run `sqlc generate`** to create Go code
4. **Implement handlers** in `internal/api/`
5. **Add routes** in `main.go`
6. **Write tests** in corresponding `*_test.go` files

## Security Considerations

- Passwords are hashed using **Argon2id** (OWASP recommended)
- JWT tokens are signed with a secret key (set via `JWT_SECRET`)
- Refresh tokens expire and can be revoked
- SQL queries are parameterized (via sqlc)
- Use HTTPS in production
- Set strong `JWT_SECRET` and `POLKA_KEY` values
- Never commit `.env` file to version control
